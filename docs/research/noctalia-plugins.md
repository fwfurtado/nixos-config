# Noctalia plugins: declarative installation

**Conclusion:** Yes. At the pinned Noctalia revision, `home/fernando/desktop/noctalia-plugins.nix` supplies revision-pinned, hashed official/community plugin directories as read-only `path` sources. `noctalia-settings.toml` enables the five plugin IDs. No imperative activation-time install is needed. [Local pin](../../.tack/pins.lock.json), [pinned module](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/nix/home-module.nix), [plugin docs](https://docs.noctalia.dev/noctalia/plugins/).

## Why this works at this pin

- `programs.noctalia.settings` is an attrset converted to TOML (or a TOML string/path); the Noctalia module links `config.toml` into XDG config and optionally validates it. It does **not** expose a separate `programs.noctalia.plugins` installation option. [Pinned HM module, settings](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/nix/home-module.nix#L39-L83), [generation](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/nix/home-module.nix#L102-L148).
- The actual Noctalia config schema supports `[plugins].enabled`, `[plugins].auto_update = "none"`, and `[[plugins.source]]` objects with `name`, `kind = "path"`, `location`, and `enabled`. Path sources are explicitly intended to be immutable directories (including Nix store paths), read-only and not updated by Noctalia. An explicit source list replaces the defaults; leaving the list unspecified would otherwise seed the mutable official/community Git URLs. [Types and defaults](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/config/config_types.h#L1727-L1778), [source schema](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/config/schema/config_schema.cpp#L543-L614), [default source implementation](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/config/config_types.cpp#L60-L85), [source default fallback](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/config/config_service.cpp#L1752-L1755).
- Registry scanning checks `<source-root>/<plugin-subdir>/plugin.toml`, matches the manifest's canonical `author/plugin` ID against the enabled filter and plugin API range, then loads entries directly from that source root. It does not need a mutable checkout or materialization for path sources. The materialization worker operates only on `kind = "git"`. Pinned shell accepts plugin API levels 3–32; the manifests below declare 3, 9, or 26. [Registry](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/scripting/plugin_registry.cpp#L34-L109), [path resolution](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/scripting/plugin_source_paths.cpp#L59-L67), [materialization](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/scripting/plugin_manager.cpp#L327-L341), [API range](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/scripting/plugin_api.h#L7-L40).
- The alternative `noctalia msg plugins enable <id>` command exists but is imperative: for Git sources it fetches/exports plugin code under the app-owned state directory. Declarative `enabled` with Git URLs also auto-fetches at Noctalia startup, but this is not build-time pinning and needs runtime network access. Path sources remove that dependency for plugin **code**. [Official plugin install docs](https://docs.noctalia.dev/noctalia/plugins/), [pinned startup materialization](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/scripting/plugin_manager.cpp#L327-L446), [pinned IPC](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/app/application_ipc.cpp#L656-L740).

## Integration and secrets boundary

`home/fernando/desktop/default.nix` imports the plugin sources alongside `./noctalia.nix`, without importing Noctalia's upstream module twice. The additional source settings and Python dependencies apply only to the mini-PC; the snapshot in `noctalia-settings.toml` supplies enabled IDs and widget instances. Niri's `Mod+Shift+Slash` invokes the installed cheatsheet plugin. [Local desktop imports](../../home/fernando/desktop/default.nix), [snapshot](../../home/fernando/desktop/noctalia-settings.toml), [Niri cheatsheet example](https://github.com/noctalia-dev/community-plugins/blob/795a3f1d8b11501bbd89684f56e2e9905233665d/keybind-cheatsheet/README.md#L44-L73).

**Keep the Wallhaven API key out of the Nix store.** Noctalia's Home Manager module renders its settings to a world-readable store file; Wallhaven reads `api_key` from plugin settings, not an environment variable. The separate `secrets/noctalia-wallhaven.enc` decrypts to an owner-only TOML file at `/run/secrets/noctalia-wallhaven`; Home Manager links it into the Noctalia config directory without copying plaintext to the store. The state-dir `settings.toml` still wins if it contains an overriding key, and is plaintext. [Pinned HM module](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/nix/home-module.nix#L126-L139), [Wallhaven manifest](https://github.com/noctalia-dev/official-plugins/blob/d097eb5e197f5714bef80b2185cdf60bb4b8aae8/wallhaven/plugin.toml#L12-L17), [merge precedence](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/config/config_service.cpp#L1482-L1515).

If carrying over an existing app state, check `$XDG_STATE_HOME/noctalia/settings.toml` for stale `[plugins].enabled`, `[[plugins.source]]`, or `[plugins].auto_update` overrides: sidecar values override the Nix-generated file and GUI enable/disable writes `[plugins].enabled` there. Preserve unrelated user state; remove only conflicting plugin overrides as appropriate. [Pinned merge order](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/config/config_service.cpp#L1482-L1515), [GUI override write](https://github.com/noctalia-dev/noctalia/blob/4da7a84135070f92333968be9d1486edb7cf8e2b/src/config/config_overrides.cpp#L904-L942).

The integrated mini-PC generation builds and validates Noctalia's generated TOML. An isolated runtime config-directory smoke test verified that the decrypted secret overlays the five enabled plugins without entering the Nix store. Graphical activation on the mini-PC still requires a real login. Wallpaper Depth's model must initially be installed through the plugin manager panel.
